# FIX-0002 — raport LLM

## Co zrobiono
Zdiagnozowano i naprawiono usługę systemd --user `mikowhy-teams-dashboard`, która utknęła w stanie `activating` / crashloop po restarcie.

Diagnostyka:
- `systemctl --user status mikowhy-teams-dashboard` — usługa przechodziła cykle `Started` → `Main process exited, code=exited, status=1/FAILURE` → `Scheduled restart job`, w nieskończoność (Restart=always, RestartSec=3).
- `journalctl --user -u mikowhy-teams-dashboard -n 100` — potwierdzało powtarzające się błędy wyjścia kodem 1.
- Logi w `.agents/logs/dashboard.service.log` oraz `.agents/logs/dashboard.log` — ujawniały przyczynę:

```
OSError: [Errno 98] Address already in use (while attempting to bind on address ('0.0.0.0', 8767))
```

w `engine/ws_gateway.py:235` (`WsGateway.start`) wywoływane z `engine/dashboard.py:3719` (`main`).

Przyczyna awarii: port WebSocket `8767` był już zajęty przez inny proces, więc każda próba startu dashboardu kończyła się błędem bind() i wyjściem procesu z kodem 1. systemd uruchamiał usługę na nowo, która ponownie się wysypywała — crashloop.

Obecny stan: konflikt na porcie 8767 ustąpił (zwolniony przez wcześniejszy proces). Usługa wystartowała pomyślnie o 16:49:14 CET i należy do PID 2584028 (`python3 -m engine.dashboard --port 8765 --host 0.0.0.0`), nasłuchując na portach 8765 (HTTP) oraz 8767 (WebSocket).

## Zmienione pliki
Brak zmian w kodzie — awała miała charakter konfliktu portów (środowiskowy), nie błędu w kodzie aplikacji. Nie modyfikowano żadnych plików w worktree.

## Jak zweryfikować (komendy)
```
systemctl --user is-active mikowhy-teams-dashboard      # oczekiwany: active
systemctl --user status mikowhy-teams-dashboard --no-pager  # Active: active (running)
ss -tlnp | grep -E '8765|8767'                          # oba porty nasłuchujące przez python3 (PID usługi)
journalctl --user -u mikowhy-teams-dashboard -n 20 --no-pager  # brak nowych błędów bind
```

## Ryzyka / uwagi
- Jeśli inny proces ponownie zablokuje port 8767, usługa wróci do crashloopu (Restart=always). Warto rozważyć zmianę `ws_port` lub detekcję wolnego portu w `engine/ws_gateway.py`, jeśli problem się powtórzy.
- Logi usługi: `/home/miko/apps/mikowhy-teams/deploy/logs/dashboard.service.log`.
